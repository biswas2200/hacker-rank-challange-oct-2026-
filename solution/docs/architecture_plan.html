Ghost Data deletion-audit agent: blueprint

M0 setup · doneM1 evidence loading · doneM2 identity & linking · in reviewM3 state & policy · doneM4 steps, output & eval · doneM5–M7 · not startedSamples: status 32/32 · step F1 97.6%Updated 2026-10-25

The agent reads a deletion request, works out who the person is (including old emails), finds every copy of their data, reconstructs what was true at audit_at, applies deletion_rules.csv, and writes an ordered plan of findings, remediation and verification steps to output.csv.

518requests to audit
32sample cases with answers (22 INCOMPLETE, 10 COMPLETE)
94evidence files: 28 JSON, 26 logs, 24 SQL, 11 PNG, 4 PDF, 1 TXT
4,011activity rows, including decoys and unrelated users

Design principles

  • Evidence over claims. reported_status and reported_result are hints. A snapshot captured at or before audit_at decides the state.
  • Deterministic core. Same input, same output, byte for byte. Sorting and JSON serialization are fixed.
  • Gemini for perception only. It classifies request intent and reads images and PDFs. It never decides a status.
  • Cache everything the model produces. A second run costs zero tokens and runs offline.
  • Measure against the 32 samples on every change.

What “COMPLETE” means here

  • Every relevant copy got the treatment its rule requires (delete, redact, anonymize, retain).
  • No active sync, import or restore path can recreate the data.
  • Retained records keep only permitted identifiers. Tombstones keep user_id only.
  • Records the policy says to keep still exist.

Anything else is INCOMPLETE. A request that doesn’t ask for deletion is NOT_APPLICABLE with [].

Determinism

Sorted iteration everywhere, temperature 0, cached model output, json.dumps(sort_keys=True, separators=(",",":")).

Cost

About 26 Gemini calls in a cold run (11 classification batches + 15 media files). Zero on a warm run.

Resilience

--no-llm runs fully offline from cache and keyword rules. Failed batches retry with backoff, then fall back.

Traceability

Every step carries the evidence_id that proved it. A --explain case_11 flag prints the decision trail.

Security

No API key at all: Gemini runs on Vertex AI with Application Default Credentials. .env holds only optional project/model overrides and is git-ignored.

Stack

Python 3.14.4, stdlib sqlite3/csv/json, google-genai 2.33.0, pypdf 6.21.2, python-dotenv 1.2.4.

Dataset relationships

The manifest doesn’t say which case a file belongs to. The links run through contents: email → user_id → resource_id → evidence rows.

Core data models (models.py)

@dataclass(frozen=True)
class RawEvidenceRecord:     # what a loader emits
    file_id: str; observed_at: datetime
    location: str           # SQL table / JSON path / log line
    fields: dict            # flattened field → value
    system_hint: str|None
    is_listing_row: bool    # a dump row exists by being listed

@dataclass(frozen=True)
class Observation:           # what RecordNormalizer emits
    file_id: str            # evidence_03
    observed_at: datetime   # when the fact was true
    location: str           # "replica" in it ⇒ replica copy
    resource_id: str        # search_052
    system_id: str          # search_service
    data_category: str|None # SEARCH_INDEX_ENTRY (if stated)
    presence: Presence      # PRESENT / ABSENT / UNSTATED
    stated_condition: str|None  # IDENTIFIABLE, ANONYMIZED, DELETED…
    subject_user_id: str|None   # user_32
    emails, phones, names, email_hashes: frozenset[str]
    parent_resource_id: str|None  # account_006 for search_001
    is_flow_enabled: bool|None
    is_restore_allowed: bool|None

# visibility uses observed_at <= audit_at;
# citing a file needs captured_at <= audit_at

class Condition(Enum):         # core/state.py
    ABSENT PRESENT_IDENTIFIABLE PRESENT_DEIDENTIFIED
    FLOW_ACTIVE FLOW_DISABLED RESTORE_OPEN RESTORE_BLOCKED UNKNOWN

@dataclass(frozen=True)
class SnapshotListing:         # a complete store listing
    file_id; observed_at; system_id; location
    resource_ids: frozenset[str]  # missing ⇒ gone

@dataclass
class SubjectProfile:
    user_id: str
    emails: set[str]; phones: set[str]
    names: set[str];  email_hashes: set[str]
    identity_change_audit_ids: list[str]
    # searchable_identifiers excludes names (decoy namesakes)

@dataclass
class ResourceLink:
    resource_id: str; system_id: str
    reasons: set[LinkReason]  # EVIDENCE_IDENTIFIER, CATALOG_LINK,
                              # PARENT_RESOURCE, WORKFLOW_WINDOW
    proof_ids: set[str]; aliases: set[str]

@dataclass(frozen=True)
class ResourceState:
    resource_id: str; system_id: str
    condition: Condition
    evidence_id: str|None   # file or activity that proves it
    as_of: datetime|None
    stated_category: str|None   # from evidence
    intended_action: str|None   # what the workflow tried
    latest_activity_id: str|None  # citation fallback

@dataclass(frozen=True)
class Decision:
    state: ResourceState
    treatment: Treatment    # DELETE/REDACT/ANONYMIZE/RETAIN/
                            # BLOCK_RESTORE/DISABLE_FLOW
    finding: Operation|None # None ⇒ compliant
    remediation: Operation|None
    verification: Operation

@dataclass
class Step:
    step_no: int; phase: Phase; system_id: str
    resource_id: str; operation: Operation
    state: str; evidence_id: str

Key algorithms

State at audit_at (StateReconstructor.state_at, built)

obs = index.by_resource(rid, cutoff), inside the episode,
      from files captured by the cutoff
reading(o):
  data_flow: enabled / ACTIVE → FLOW_ACTIVE, else FLOW_DISABLED
  backup:    restore_allowed / eligible → RESTORE_OPEN,
             deletion_block / decision=deny → RESTORE_BLOCKED
  other:     404 / rows=0 / NOT_FOUND → ABSENT
             present + name/email/phone/hash → PRESENT_IDENTIFIABLE
             present without them → PRESENT_DEIDENTIFIED
latest reading wins; a replica still holding the record
  beats a "gone" reading (replication drift)
nothing? → complete store listing taken after the last
  workflow action that omits the record → ABSENT
nothing? → connector / restore-access check activity
nothing? → UNKNOWN (no finding; claims are not proof)

Linking (ResourceLinker.link, built)

start = episodes.starts_after(request)   # repeat requester?
keep(x) = start is None or x.time > start
links  = evidence obs carrying any identifier   (keep)
       + LINK_RESOURCE_IDENTITY naming the person (keep)
       + parents / children of linked records   (keep)
       + matcher.matched_activities(case_id)
# matcher, for records that name nobody:
candidates = deletion_worker activity in
             [reported_at − 1.5h, min(reported_at + 2h, audit_at)]
             of deletion requests only
drop: owned by another person · type already proven ·
      other wording family · claim mismatch (accounts)
repeat until stable; then pair k-to-k ties in order
(marked paired = guess)

Rule → treatment (PolicyEngine.evaluate, built: category stated in evidence → workflow’s attempted action → resource type)

USER_PROFILE, SECONDARY_IDENTIFIER, SEARCH_INDEX_ENTRY,
CACHE_ENTRY, SUPPORT_ATTACHMENT, USER_EXPORT,
MARKETING_PROFILE                       → DELETE   (target ABSENT)
SUPPORT_MESSAGE, EMAIL_DELIVERY_LOG     → REDACT   (target REDACTED)
ACCOUNT_TOMBSTONE                       → REDACT   (keep user_id only)
ANALYTICS_PROFILE, PRODUCT_TELEMETRY    → ANONYMIZE
SECURITY_AUDIT_LOG, LEGAL_HOLD_RECORD   → RETAIN   (target PRESENT)
BACKUP_ARCHIVE                          → RETAIN + BLOCK_RESTORE
DATA_FLOW (sync/import connector)       → DISABLE

compliant = state == target
finding   = REMAINING_RECORD if target ABSENT and state PRESENT
          | EXPOSED_PII     if target REDACTED/ANONYMIZED and PII_EXPOSED
          | ACTIVE_DATA_FLOW / RESTORE_RISK for flows and backups

Step ordering (StepPlanner._sort_key)

PHASE = [FINDING, REMEDIATION, VERIFICATION]
OP_ORDER = [
  REPORT_REMAINING_RECORD, REPORT_EXPOSED_PII,
  REPORT_ACTIVE_DATA_FLOW, REPORT_RESTORE_RISK,
  DISABLE_DATA_FLOW, BLOCK_RESTORE, DELETE_RECORD,
  REDACT_RECORD, ANONYMIZE_RECORD,
  VERIFY_RECORD_ABSENT, VERIFY_RECORD_PRESENT,
  VERIFY_RECORD_REDACTED, VERIFY_RECORD_ANONYMIZED,
  VERIFY_DATA_FLOW_DISABLED, VERIFY_RESTORE_BLOCKED]
key = (PHASE.index(p), OP_ORDER.index(op), system_id, resource_id)
# flows/restores sort before deletes in REMEDIATION,
# which is the "stop recreation first" rule for free.

Status and verification set (CaseAuditor.audit)

if intent != DELETE:          return NOT_APPLICABLE, []
profile = identity.resolve(email, audit_at)
decisions = [policy.evaluate(state.state_at(r)) for r in linker.link(profile)]
decisions += risks.detect(profile, audit_at)
bad = [d for d in decisions if not d.compliant]
if not bad:
    return COMPLETE, verifications(decisions, cite=True)
return INCOMPLETE, findings(bad, cite=True)
                 + remediations(bad, evidence="")
                 + verifications(decisions, evidence="")
# verification covers ALL relevant resources (samples:
# account ABSENT + audit_record PRESENT appear even when
# only search_052 needed fixing)

09 · AI integration layer

Gemini: two jobs, both cached

Job 1 · Intent classification

518 request texts in several languages (English, Spanish, French and Japanese appear in the samples). Gemini returns one label per case. A keyword classifier runs alongside it, and any disagreement is printed for review.

Prompt (llm/prompts/intent.md), batched ~50 per call:
"For each request decide whether the person asks
 to DELETE / ERASE their account or personal data.
 Labels: DELETE, ACCESS, EXPORT, CORRECTION,
 OPT_OUT, OTHER. Requests to verify or finish an
 earlier deletion count as DELETE."
response_schema:
 [{case_id: str, intent: enum, confidence: number}]
temperature: 0
Job 2 · Image & PDF extraction

11 console screenshots and 4 PDFs hold record rows (resource_id, system, status, identifiers). Each file is sent once. The JSON result joins the same EvidenceIndex as parsed SQL rows.

Prompt (llm/prompts/media_extract.md):
"List every record visible in this file. For each:
 system_id, resource_id, data_category, status,
 subject_reference, name, email, phone, email_hash,
 timestamps. Use null for anything not shown.
 Do not guess."
PDF path: pypdf text first; Gemini only if empty.
cache key: sha256(file bytes + prompt version)
Access: Vertex AI with Application Default Credentials (gcloud auth application-default login), model gemini-3.6-flash on the global endpoint. No API key exists anywhere in the project. Status: the keyword half of Job 1 is built (M2); the Gemini calls come in M5.
Gemini never decides a status or a step. The policy engine and planner are plain Python, so a model mistake can only affect which records are seen, never how they are judged. Model mistakes are also visible in the cache and can be corrected by hand.
